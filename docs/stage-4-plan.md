# 阶段四拆分：跨日经营、成长与存档

阶段四的最终目标是：从新游戏开始，连续经营多个营业日，通过采购、雇佣、布置、升级和扩建改善经营，并在重启游戏后继续原进度。本页将原计划第 8 节拆成六个连续的小版本。每个小版本都应能单独试玩、测试和提交；后一个版本建立在前一个版本的数据与交互上。

当前按需求先实现 4.5，暂缓 4.4；家具与设备在跨营业日中保留，退出程序后的存档将在 4.4 补齐。

当前阶段三仍是单日试玩：金币和员工设置随“新营业日”重置，员工默认在场，食材无限，四张桌子固定。阶段四会逐步替换这些临时规则，不一次性重写现有做菜、顾客和员工逻辑。

| 小版本 | 交付重点 | 完成后玩家获得的选择 |
|---|---|---|
| 4.1 跨日经营骨架 | 开店前 / 营业 / 日结流程，常驻资金和账本 | 用上一日收入开始下一日 |
| 4.2 采购与菜单 | 食材库存、订单预留、采购、菜单开关 | 决定买什么、卖什么 |
| 4.3 雇佣与工资 | 正式雇佣一名员工，锁定并支付日工资 | 在节省人力和控制成本间取舍 |
| 4.4 本地存档 | 日结保存、继续游戏、新游戏、备份和版本 | 安全地跨会话经营 |
| 4.5 家具与设备 | 非营业时移动家具、购买餐桌、升级烹饪设备 | 调整服务能力和工作动线 |
| 4.6 扩建与调优 | 固定区域扩建、寻路更新、经济与多日验证 | 达成首次扩店目标 |

## 4.1 跨日经营骨架

**实现范围**

- 将当前“重置整局”拆成“开始新档”和“开始下一营业日”。订单、污渍、角色手持物等按日清空；金币、累计天数、员工配置及后续成长数据保留。
- 增加开店前状态和日结后状态。只有开店后才生成顾客、推进营业时间；日结只执行一次，下一日从开店前界面进入。
- 建立经营账本，分别记录顾客付款、采购、工资、家具、设备和扩建支出。金币变动走统一入口，拒绝余额不足和重复扣款。
- 日结显示日初现金、当日收入、各项支出、日末现金、服务数量和评价；将“当日现金变化”与之后要加入的“食材消耗成本”分开。

**验收**：连续经营三天，订单和临时任务每天清空，现金与天数持续累积；重复点击结算或开店不会重复发钱；阶段三完整服务流程仍可运行。

## 4.2 采购与菜单

**实现范围**

- 为两道菜定义食材需求和固定采购单价；库存区分总量、已为订单预留的量和可用量。
- 开店前提供采购界面，显示单价、数量、合计、余额以及每道菜可制作的份数。采购立即付款，余额不足不成交。
- 菜单开关控制顾客可点的菜。生成订单前必须确认菜品启用且食材可预留；多单同帧到来不能超卖。
- 订单等待时预留食材，开始烹饪时实际消耗；开工前取消或顾客离店则释放预留，开工后不返还已消耗食材。主角接手员工预约任务时不能重复扣料。
- 保留可负担的基础菜及有限应急补给，避免缺钱缺料后无法继续经营。

**验收**：库存不会为负；停卖的菜不被点到；同时到来的订单不超过可用食材；取消与超时按开工前后正确释放或消耗；采购不能透支。

## 4.3 雇佣与工资

**实现范围**

- 新档不再默认正式雇佣员工；开店前可雇佣或停止雇佣一名员工，营业中不变更关系。员工工作开关和优先级跨日保留。
- 进入开店前准备时为已雇员工锁定当天工资；准备阶段雇佣或停止雇佣时立即重算。采购只能使用扣除锁定工资后的余额，日结时只支付一次。若现金不够，明确提示员工当天不出勤，玩家仍能自己营业。
- 日结同时列出营业收入、食材消耗成本估计、工资和经营收益估计，方便判断雇佣是否划算。

**验收**：雇佣状态决定员工是否出现和工作；无法重复雇佣、重复支付工资或产生负数余额；资金不足时可继续手动经营；员工未开工任务仍可由主角接手。

## 4.4 本地存档

**实现范围**

- 仅在日结清场后及开店前保存，不恢复营业中途的订单、角色位置或任务预留。
- 存档包含版本、天数、现金、库存、菜单、员工及其设置，并预留家具位置、升级和扩建字段。保存稳定标识与数值，不保存节点引用。
- 先写临时文件，再替换正式文件；保留上一个有效备份。读取时补齐缺失的可选字段；坏档提示恢复备份。
- 标题界面提供“继续游戏 / 新游戏”；覆盖已有进度前在游戏内确认。

**验收**：退出并重启后，已实现的经营数据一致；缺失可选字段可加载；坏档不被静默覆盖；新游戏确实清空旧进度。

## 4.5 家具与设备

**实现范围**

- 开店前提供家具布置模式：移动已有家具、预览新位置、确认或取消。检查边界、碰撞、入口到餐桌及工作台的通路、必要操作点可达性。取消后恢复原位置和金币。
- 支持购买至少一张餐桌；餐桌数量不再写死为四张，顾客分桌、订单卡与员工寻路按当前布局生成。
- 提供一项烹饪设备升级，明确显示价格和效果；效果同时作用于主角小游戏与员工做菜，并在重开游戏后保留。

**验收**：无法把家具放到不可达或重叠处；购买和升级只扣款一次；新增餐桌能接客、上菜和收盘；旧桌与员工路线不回归。

## 4.6 扩建与经济调优

**实现范围**

- 在日结或开店前购买一次固定区域扩建，更新地图边界、可放置范围和角色寻路；扩建状态可存档。
- 补齐完整日结，包括现金变化、经营收益估计与主要经营问题提示。
- 用固定客流脚本和人工试玩校准首日资金、食材价格、员工工资、设备与扩建价格。首次雇佣应在前几个营业日可负担，首次扩建不依赖无聊的重复刷天数。
- 验证资金紧张时可通过基础菜和有限应急补给恢复。

**扩建界面方案**

- 开店准备页增加“扩建餐厅”入口，显示扩建价格、当前可用金币、扩建后新增的地面面积，以及能做什么（摆更多餐桌、设备可移入新区域）。余额不足时仍能打开详情查看目标，但不能确认购买。
- 点击入口进入扩建预览：左侧展示当前布局的小地图，右侧以半透明地板和虚线墙框标出右侧固定扩建区；写清扩建前后的营业面积。底部只有“确认扩建”和“返回”两个操作。确认前不扣金币，购买后不能重复购买。
- 确认后播放简短的拆墙/铺地动画，更新房间背景、边界、相机范围和布置校验；随后自动打开“家具设备”页，让玩家立刻把现有餐桌或设备拖到新区域，或继续购买新餐桌。营业中不允许扩建。
- 扩建完成后的入口改为“已扩建”，可再次打开平面图查看布局；日结账本单独显示扩建费用。4.4 存档恢复时也应显示同一状态。

**验收**：从新档连续完成至少五个营业日，首次雇佣、设备升级和扩建均可达；扩建后角色进入新区域，订单与旧家具正常；存档重启后布局和成长一致；不存在永久占位、负库存、重复扣款或资金死局。

## 实施顺序与边界

按 4.1 → 4.2 → 4.3 → 4.4 → 4.5 → 4.6 开发。每个小版本结束时跑完整 Godot 回归测试，并实际试玩关键流程。4.1 先固定跨日数据结构与账本接口，4.4 再接入文件读写，避免把场景节点直接塞进存档。4.5 的新增餐桌会改变当前固定四桌假设，应单独完成并回归，而不是混入库存或雇佣改动。

首个动手项是 **4.1：跨日经营骨架**。完成它之后，采购、工资、升级和扩建都能接入同一套资金与日结流程。
